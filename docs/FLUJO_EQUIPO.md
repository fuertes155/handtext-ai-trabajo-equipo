# Flujo de trabajo

1. Usar la cuenta propia. No compartir contraseñas ni tokens.
2. Antes de modificar: `git status`, leer la issue, actualizar `main` solo si el árbol está limpio y revisar requisitos.
3. Crear una rama como `samuel/T001`, `juan-miguel/T005` o `luis-miguel/T002`, según la tarea realmente asignada.
4. Configurar el nombre y correo verificado o noreply de la cuenta propia. Configurar Git no inicia sesión ni prueba autoría.
5. Realizar una tarea o parte coherente, probar y revisar `git diff` y `git diff --cached`. Añadir archivos explícitos, no carpetas de secretos.
6. Crear un commit descriptivo con la identidad propia. No alterar fechas, autores o historial para aparentar aportes. El trabajo conjunto puede indicar coautoría con acuerdo de quienes participaron.
7. Subir la rama y abrir un PR hacia `main`. Incluir `Closes #numero`, alcance, resultados de pruebas y cualquier procedencia del material reutilizado.
8. Otro integrante revisa. Integrar solo cuando los criterios estén cumplidos. No cerrar tareas solo porque estuvieron hechas en el proyecto anterior.
